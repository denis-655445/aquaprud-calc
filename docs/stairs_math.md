### 0.2 Система координат (2D-схема)

- Початок — лівий верхній кут прямокутника, що описує ставок.
- Вісь **x** — вправо (вздовж довжини L), вісь **y** — **вниз** (вздовж ширини W), як на екрані.
- **n** — одиничний вектор нормалі до стінки, спрямований **всередину** ставка.
- **L — завжди довша сторона.** Якщо майстер ввів W > L, для побудови схеми міняємо їх місцями (результати площ і об'ємів від цього не змінюються).
- **Квадрат** — прямокутник з `|L − W| ≤ 1 % · max(L, W)`. **Коло** — овал з тією самою умовою.

### 0.4 Округлення (без змін з v4, D18)

- Кількість у `шт` — вгору до цілого.
- `м`, `м²`, `м³` у кошторисі — до 0,1.
- Роботи й націнка — до цілих гривень.
- Проміжні геометричні розрахунки — **без округлення**; округлюємо лише те, що показуємо чи записуємо в кошторис.

Значення з позначкою «ЗАПОВНИТИ» задає майстер у вкладці «Налаштування». Поки воно порожнє, калькулятор показує попередження і не рахує залежні величини.

| Поле | Значення | За замовчуванням |
|---|---|---|
| Кількість | 0 («без сходів») … `steps_max` | 0 |
| Тип | `shelf` (полиця) / `platform` (платформа) | `shelf` |
| Край | `straight` (прямі) / `round` (округлі) | `straight` |
| Точки | масив номерів точок схеми | — (обов'язково) |
| w_c | ширина по центру, м | `shelf_width_default_m` |
| w_e | ширина на кінцях, м | прямі: = w_c; округлі: 0 |
| Глибина | см | k-те значення з `shelf_depths_cm` |

**Правила полів:**
- Глибину за замовчуванням беремо з «Налаштувань», майстер може змінити її в полі на об'єкті. У кошторис записується **фактичне** значення, тож зміна налаштувань не змінює старі кошториси (як знімок цін, D6).
- Точки обов'язкові: вони задають, **де** сходинка. Кнопка «Розміри» задає лише w_c, w_e і глибину. Сходинка без точок — помилка E1 (підсвічуємо при збереженні).
- Поле w_e показуємо лише для прямокутника й квадрата: на кривій стінці w_e завжди 0 (§7.2).
- Для форми `custom` сходинки в MVP недоступні: 2D-схема для неї не визначена.

## 4. Схеми точок

Схема залежить від типу сходинки: **платформа** — 6 точок (прямокутник) або 4 (квадрат, коло, овал); **полиця** — 8 точок для всіх форм. Номери #1–#6 у 8-точковій схемі не змінюються.

### 4.1 Прямокутник (L > W)

| № | Положення | Координати | Кут | Нормаль n |
|---|---|---|---|---|
| #1 | лівий верхній кут | (0, 0) | так | (1, 1)* |
| #2 | середина верхньої стінки | (L/2, 0) | ні | (0, 1) |
| #3 | правий верхній кут | (L, 0) | так | (−1, 1)* |
| #4 | лівий нижній кут | (0, W) | так | (1, −1)* |
| #5 | середина нижньої стінки | (L/2, W) | ні | (0, −1) |
| #6 | правий нижній кут | (L, W) | так | (−1, −1)* |
| #7 | середина лівої стінки (лише 8 т.) | (0, W/2) | ні | (1, 0) |
| #8 | середина правої стінки (лише 8 т.) | (L, W/2) | ні | (−1, 0) |

\* У куті n = n₁ + n₂ — сума нормалей двох стінок, **не нормована**. Тоді `P + w · n` — внутрішній кут на відстані w від обох стінок.

**Порядок обходу** (за годинниковою): 6 точок — `1, 2, 3, 6, 5, 4`; 8 точок — `1, 2, 3, 8, 6, 5, 4, 7`.
**g точок:** #1 = 0, #2 = L/2, #3 = L, #8 = L + W/2, #6 = L + W, #5 = 1,5L + W, #4 = 2L + W, #7 = 2L + 1,5W. Периметр P = 2(L + W).
**Нормалі стінок:** верхня (0, 1), права (−1, 0), нижня (0, −1), ліва (1, 0).

### 4.2 Квадрат (L = W = a)

| № | Положення | Координати | g |
|---|---|---|---|
| #1 | лівий верхній кут | (0, 0) | 0 |
| #2 | правий верхній кут | (a, 0) | a |
| #3 | лівий нижній кут | (0, a) | 3a |
| #4 | правий нижній кут | (a, a) | 2a |
| #5 | середина верхньої (8 т.) | (a/2, 0) | a/2 |
| #6 | середина правої (8 т.) | (a, a/2) | 1,5a |
| #7 | середина нижньої (8 т.) | (a/2, a) | 2,5a |
| #8 | середина лівої (8 т.) | (0, a/2) | 3,5a |

Порядок: 4 точки — `1, 2, 4, 3`; 8 точок — `1, 5, 2, 6, 4, 7, 3, 8`. Кути — #1–#4.

### 4.3 Овал і коло

Центр `(cx, cy) = (L/2, W/2)`, півосі `a = L/2`, `b = W/2`. Точка з параметричним кутом θ (на екрані 270° — угорі):

```
x = cx + a · cos θ
y = cy + b · sin θ
n = −(cos θ / a, sin θ / b) / ‖(cos θ / a, sin θ / b)‖      // нормаль всередину
```

| № | θ | Положення |
|---|---|---|
| #1 | 180° | лівий торець |
| #2 | 270° | верх |
| #3 | 0° | правий торець |
| #4 | 90° | низ |
| #5 | 225° | вгорі ліворуч (8 т.) |
| #6 | 315° | вгорі праворуч (8 т.) |
| #7 | 45° | внизу праворуч (8 т.) |
| #8 | 135° | внизу ліворуч (8 т.) |

Порядок: 4 точки — `1, 2, 3, 4`; 8 точок — `1, 5, 2, 6, 3, 7, 4, 8`. Кутів немає.

**Довжина дуги** g(θ) рахується чисельно — сумою хорд з кроком 0,125° (2880 кроків). Таблиця будується один раз на ставок; зворотна функція θ(g) — бінарним пошуком у таблиці.

## 5. Сходинки — загальна модель

1. **Кожна сходинка — окремий шар.** Вона будується від стінки з нуля, зі своїми точками, ширинами й глибиною. Шари не залежать один від одного.
2. **Перекриття.** Якщо шари накладаються, у спільній зоні діє мілкіший. Порядок — за глибиною, а не за порядком додавання (§9).
3. **Два типи.** Полиця (§7) — смуга вздовж стінки між вибраними точками. Платформа (§8) — широка мілка зона, відрізана хордою.
4. **Два види краю** для обох типів: прямі (ламана / хорда) і округлі (одна дуга кола).
5. **Вид полиці** за ширинами: `w_c > w_e` — опукла, `w_c = w_e` — пряма, `w_c < w_e` — увігнута. Підпис показуємо автоматично.
6. **Кількість** — перемикач як у ліхтарів: «без сходів / 1 / 2 / 3». У MVP `steps_max = 3`.
7. **Глибина** кожного шару: `0 < h_k < D`. Два шари з однаковою глибиною об'єднуються.

## 6. Прогін: які точки утворюють сходинку

Вибрані точки перетворюємо на один або кілька **прогонів** — неперервних ділянок периметра.

**Алгоритм:**
1. Проходимо точки схеми в порядку обходу і позначаємо вибрані.
2. Якщо вибрано всі — це **кільце**.
3. Знаходимо **розриви** — неперервні групи невибраних точок (циклічно).
4. Найбільший розрив відділяє глибоку зону. Якщо найбільших розривів кілька однакових — ділимо в кожному з них: сходинка складається з кількох частин.
5. Решта розривів **перекриваються**: невибрана точка між вибраними не розриває сходинку (ескіз 6).
6. Для кожної частини: `seq` — усі точки від кінця до кінця (з перекритими), `sel` — лише вибрані, `A = seq[0]`, `B = seq[last]`.

**Приклади (прямокутник, 6 точок):**

| Вибрано | Розриви | Частини |
|---|---|---|
| #1 #3 #4 | {#2} = 1, {#6 #5} = 2 | одна: 4-1-2-3, A = #4, B = #3 |
| #1 #2 #4 #5 | {#3 #6} = 2 | одна: 5-4-1-2, A = #5, B = #2 |
| #2 #5 | {#3 #6} = 2, {#4 #1} = 2 | дві: {#5} і {#2} |
| #1 #4 | {#2 #3 #6 #5} = 4 | одна: 4-1 |

```js
// Прогони: повертає 'ring' або масив частин {seq, sel, ends:[A,B]}
function runs(pond, sel) {
  const o = pond.order, n = o.length, on = o.map(id => sel.includes(id));
  if (on.every(Boolean)) return 'ring';                 // усі точки — кільце
  const gaps = [];                                      // розриви: {s — початок, l — довжина}
  for (let i = 0; i < n; i++) if (!on[i] && on[(i - 1 + n) % n]) {
    let l = 0; while (!on[(i + l) % n]) l++; gaps.push({ s: i, l });
  }
  const mx = Math.max(...gaps.map(g => g.l));
  const cuts = gaps.filter(g => g.l === mx).sort((a, b) => a.s - b.s); // найбільші розриви ділять
  return cuts.map((g, k) => {
    const next = cuts[(k + 1) % cuts.length], seq = [];
    let i = (g.s + g.l) % n;
    do { seq.push(o[i]); i = (i + 1) % n; } while (i !== next.s);
    return { seq, sel: seq.filter(id => sel.includes(id)), ends: [seq[0], seq[seq.length - 1]] };
  });
}
```

## 7. Полиця

### 7.1 Послідовність побудови

```
для кожної частини прогону:
  1. якщо вибраних точок < 2                      → помилка E2
  2. A, B — кінці; Ls — довжина стінки від A до B за годинниковою
  3. corners — кути ставка строго всередині прогону (лише прямокутник і квадрат)
  4. E_A, E_B — кінцеві контрольні точки          (§7.2)
  5. M — точка стінки на відстані Ls/2 від A;  M′ = M + w_c · n(M)
  6. край:
       прямі   → ламана E_A → Q… → E_B            (§7.3)
       округлі → одна дуга через E_A, M′, E_B     (§7.4)
  7. многокутник полиці = шлях по стінці від A до B + край у зворотному порядку
  8. площа = |signedArea(многокутник)|            (§7.7)
```

### 7.2 Кінцеві контрольні точки E_A, E_B

| Де стоїть кінець | E | Що виходить |
|---|---|---|
| Крива стінка (коло, овал) | `E = A` (w_e ігнорується) | край сходиться в саму точку |
| Кут прямокутника / квадрата | `E = A + w_e · n_s`, де n_s — нормаль вибраної стінки, що виходить з цього кута | край упирається в сусідню стінку на відстані w_e від кута |
| Середина прямої стінки | `E = A + w_e · n(A)` | при w_e > 0 — прямий обріз; при w_e = 0 — край сходиться в точку |

Чому на кривій стінці w_e = 0: інакше кінець полиці був би прямим обрізом, а на криволінійних ставках полиці плавно прилягають до стінки.

### 7.3 Прямі: ламана лінія

```
край = [E_A] + проміжні + [E_B]
проміжні = Q(P) для кожної вибраної точки P всередині прогону
         + Q(кут) для кожного кута всередині прогону (навіть невибраного)
         упорядковані за g від A
якщо проміжних немає → проміжні = [M′]
Q(P) = P + w_c · n(P)          // у куті n = n₁ + n₂ → внутрішній кут
```

**Що виходить:**
- Прямокутник, одна стінка (#1 #2 #3): смуга ширини w_c, кінці впираються в бічні стінки.
- Прямокутник, L (#6 #5 #4 #1): смуга з внутрішнім кутом.
- Прямокутник, пів стінки (#1 #2): смуга з прямим обрізом біля #2.
- Овал, 8 точок (#1 #5 #2 #6 #3): ламана майже паралельно стінці.
- Овал, мало точок: з однією проміжною точкою виходить «дах» — тому полиця працює на 8-точковій схемі.

**Перевірка E9:** усі точки краю мають лежати всередині ставка. Інакше полиця ширша, ніж дозволяє форма.

### 7.4 Округлі: одна дуга кола через три точки

Край — дуга кола через E_A, M′, E_B.

**Коло через три точки** (x₁, y₁), (x₂, y₂), (x₃, y₃):

```
d  = 2 · [x₁(y₂ − y₃) + x₂(y₃ − y₁) + x₃(y₁ − y₂)]
cx = [(x₁² + y₁²)(y₂ − y₃) + (x₂² + y₂²)(y₃ − y₁) + (x₃² + y₃²)(y₁ − y₂)] / d
cy = [(x₁² + y₁²)(x₃ − x₂) + (x₂² + y₂²)(x₁ − x₃) + (x₃² + y₃²)(x₂ − x₁)] / d
R  = √((x₁ − cx)² + (y₁ − cy)²)
```

- Якщо `|d| < 10⁻⁹`, точки лежать на одній прямій: R = ∞, край — відрізок E_A → E_B.
- **Симетричний випадок** (M′ на серединному перпендикулярі до E_A E_B): `c = |E_A E_B|`, `h` = відстань від середини хорди до M′. Тоді `R = c² / (8h) + h / 2`, центр лежить на прямій M′ → середина хорди на відстані R від M′.

**Вибір напрямку дуги.** З двох дуг між E_A і E_B беремо ту, що проходить через M′:

```
t₀ = atan2(E_A − C);  Δ_B = норм(atan2(E_B − C) − t₀);  Δ_M = норм(atan2(M′ − C) − t₀)
якщо Δ_M < Δ_B → йдемо на +Δ_B, інакше → на −(2π − Δ_B)        // норм(x) ∈ [0, 2π)
```

Дугу дискретизуємо 120 відрізками.

**Обмеження:**
- **E3:** у прогоні є кут прямокутника чи квадрата. Одна дуга не може обійти кут 90° і не вийти за стінку. Підказка: «Розбийте на дві полиці або оберіть «Прямі»».
- **E4:** будь-яка точка дуги виходить за стінку більш ніж на `arc_tolerance_m` (1 см).

**Вид полиці на прямій стінці** (приклад §13, E4):

| w_c | w_e | Вид | Край |
|---|---|---|---|
| 0,6 | 0 | опукла | дуга від кута до кута, виступає у воду |
| 0,5 | 0,5 | пряма | R = ∞, пряма смуга |
| 0,3 | 0,9 | увігнута | дуга від бічних стінок, прогинається до берега |

### 7.5 Розмітка округлої полиці на об'єкті

1. Забити кілки в E_A і E_B, виміряти хорду c.
2. Від кожного кілка відміряти шнуром R. Два шнури перетнуться у двох точках — це два можливі центри.
3. Взяти центр з протилежного від M′ боку хорди, якщо дуга менша за півколо (h < R). Якщо дуга більша за півколо — з того самого боку.
4. Із центру шнуром R провести дугу від E_A через M′ до E_B.

Калькулятор показує R і c для кожної округлої полиці.

### 7.6 Кільце (вибрано всі точки)

| Форма | Прямі | Округлі |
|---|---|---|
| Прямокутник / квадрат | внутрішній прямокутник через Q усіх точок | **E5**: недоступно (огинає кути) |
| Овал | внутрішній многокутник через Q усіх точок | внутрішній овал з півосями `a − w_c`, `b − w_c` |
| Коло | внутрішній многокутник | концентричне коло `R − w_c` |

Площа кільця: `S − area(внутрішній контур)`.
Внутрішній овал — наближення: точна лінія на сталій відстані від еліпса еліпсом не є. Похибка мала, поки `w_c ≪ b`.

### 7.7 Площа многокутника (формула «шнурування»)

```
S = ½ · |Σ (x_i · y_{i+1} − x_{i+1} · y_i)|,   i = 0 … n−1,  точка n = точка 0
```

Шлях по стінці: для прямокутника — A, кути між A і B, B. Для овалу — точки з кроком не більше 1,5° (240 відрізків на повний периметр).

## 8. Платформа (правило C)

Схема — 6 точок (прямокутник) або 4 (квадрат, коло, овал). Вибір усіх точок — помилка E6 («для кільця оберіть «Полиця»»).

### 8.1 Правило B — хорда через крайні точки

Для кожної частини прогону:

```
u = одинична нормаль до відрізка A → B
орієнтація u: середнє u·p для точок поза прогоном має бути більшим за u·A
  (якщо рівне — середнє u·p для вибраних точок прогону має бути меншим за u·A)
t = u · A
платформа = ставок ∩ {p : u · p ≤ t}
```

### 8.2 Правило A — частка площі (коли B вироджується)

B **вироджується**, якщо:
- у частині одна точка (A = B);
- A і B — сусідні точки (у `seq` дві точки);
- площа за B менша за 1 % S або більша за 99 % S.

Тоді:

```
f = k / n            // k — вибраних точок у частині, n — точок у схемі
одна точка: u = n(A) нормована (у куті — бісектриса)
інакше:     u як у §8.1
t: area(ставок ∩ {u · p ≤ t}) = f · S      // бісекція, 60 ітерацій
```

**Відтинання многокутника півплощиною** (опуклий ставок):

```js
// Лишає частину многокутника, де u·p <= t (алгоритм Сазерленда — Годжмана)
function clipHalf(poly, u, t) {
  const out = [];
  for (let i = 0; i < poly.length; i++) {
    const P = poly[i], Q = poly[(i + 1) % poly.length];
    const fp = dot(P, u) - t, fq = dot(Q, u) - t;
    if (fp <= 0) out.push(P);                                  // вершина всередині — лишаємо
    if (fp * fq < 0) out.push(add(P, sub(Q, P), fp / (fp - fq))); // ребро перетинає межу
  }
  return out;
}
```

### 8.3 Округла платформа

Кінці хорди P₁, P₂ — перетин прямої `u · p = t` зі стінкою. Дуга прогинається **в бік платформи** зі стрілою:

```
c = |P₁P₂|,   h = platform_arc_k · c        // platform_arc_k = 0.1 — наше припущення
R = c² / (8h) + h / 2
S_сегмента = R² · arccos((R − h) / R) − (R − h) · √(2Rh − h²)
S_платформи_округлої = S_платформи_прямої − S_сегмента
```

## 9. Кілька шарів: видимі площі

```
шари сортуємо за глибиною від мілкого до глибокого
S_vis,k = | R_k \ ⋃ R_j для всіх j з h_j < h_k |
S_глиб  = S − Σ S_vis,k
```

- Якщо шари не перекриваються, `S_vis,k` = площа шару за формулою «шнурування» (§7.7).
- Якщо перекриваються — **інтегруванням рядками** (v1.2): у рядку на висоті y кожен шар — точні відрізки [x₀, x₁]; для шару k рахуємо довжину, не накриту об'єднанням мілкіших, і множимо на висоту рядка. Межі рядків — y усіх вершин (між ними сторони прямі, тож середина рядка дає точний результат), товсті рядки ділимо до висоти ≤ `raster_cell_m`. Код нижче (растр) — еталон v1.1, лишається в `tests/stairs_ref.js`.
- **E8:** `S_vis,k = 0` — шар повністю схований під мілкішим.

```js
// Растеризація рядками: кільця многокутника → сітка 0/1 (правило парності)
function rasterRows(rings, cell, box) {
  const [x0, y0, x1, y1] = box;
  const nx = Math.ceil((x1 - x0) / cell), ny = Math.ceil((y1 - y0) / cell);
  const grid = new Uint8Array(nx * ny);
  for (let j = 0; j < ny; j++) {
    const y = y0 + (j + 0.5) * cell, xs = [];               // центр рядка
    for (const ring of rings) for (let i = 0; i < ring.length; i++) {
      const a = ring[i], b = ring[(i + 1) % ring.length];
      if ((a[1] > y) !== (b[1] > y))                         // ребро перетинає рядок
        xs.push(a[0] + (y - a[1]) * (b[0] - a[0]) / (b[1] - a[1]));
    }
    xs.sort((p, q) => p - q);
    for (let k = 0; k + 1 < xs.length; k += 2) {             // пари перетинів = відрізки всередині
      const i0 = Math.max(0, Math.ceil((xs[k] - x0) / cell - 0.5));
      const i1 = Math.min(nx - 1, Math.floor((xs[k + 1] - x0) / cell - 0.5));
      for (let i = i0; i <= i1; i++) grid[j * nx + i] = 1;
    }
  }
  return { grid, nx, ny };
}
```

Кільце передаємо двома кільцями (зовнішнє + внутрішнє) — правило парності само робить дірку.

## 10. Об'єм, ґрунт, плівка зі сходинками

### 10.1 Об'єм

```
V = depth_profile_k · (S_глиб · D + Σ S_vis,k · h_k)
V_заг = V + V_б
```

Без сходинок формула збігається з v4: `V = S · D · depth_profile_k`.

### 10.2 Похідні величини

Усе, що залежить від V_заг, перераховується автоматично: `excavation`, `Q_потр`, а через них — підбір фільтра, УФ і насоса.

Без змін: `film_area` рахується за максимальною глибиною D (§3), геотекстиль = площа плівки. Для вертикальних підйомів сума висот сходинок дорівнює D, тому довжина шляху по стінці не змінюється.

## 11. Автопідбір обладнання та підсумок (без змін з v4)

### 11.1 Фільтр і УФ

Найдешевша активна позиція з `maxV_(fish|nofish) ≥ V_заг`.

### 11.2 Насос за напором

```
Q(H) = Q_max · (1 − H / H_max)        // лінійне наближення кривої насоса
```

1. Якщо у фільтра є `pump_kit` і `Q(H_потр) ≥ Q_потр` → «Насос: у комплекті» (0 грн).
2. Інакше — найдешевший активний насос з `Q(H_потр) ≥ Q_потр`, жирним, з приміткою «насос комплекту недостатній».
3. Якщо жоден не підходить — попередження в інтерфейсі.

*Приклад з умовними числами:* насос Q_max = 10 000 л/год, H_max = 5 м; H_потр = 1,8 м → Q = 10 000 · (1 − 0,36) = 6 400 л/год.

### 11.3 Автопозиції

`кількість = метрика(база) · коеф`. Округлення: `шт` — вгору; `м`, `м²`, `м³` — до 0,1. Ключі баз: `pond_area`, `perimeter`, `volume`, `film_area`, `bio_film_area`, `film_area_total`, `pipe_len`, `excavation`, `per_skimmer`, `per_drain`, `per_line`, `fixed`.

### 11.4 Підсумок

```
Роботи  = round(labor_pct / 100 · (Σ Обладнання + Σ Матеріали)) + Σ ручні позиції work
Націнка = round(markup_pct / 100 · (Σ Обладнання + Σ Матеріали + Роботи))
Разом   = Σ Обладнання + Σ Матеріали + Роботи + Націнка
```

- `labor_base = materials+equipment`; роботи й націнка — цілі гривні (D18).
- У тексті для клієнта націнка входить у «Монтажні роботи», знижка — окремим рядком (D21).
- «Приховати ціни» лише ховає суми на екрані.
- Перед реалізацією звірити цей запис із `core/calc.js` v0.2.0: сходинки порядок підсумку не змінюють.

```js
// Площа многокутника зі знаком (формула «шнурування»)
function signedArea(poly) {
  let s = 0;
  for (let i = 0; i < poly.length; i++) {
    const a = poly[i], b = poly[(i + 1) % poly.length];
    s += a[0] * b[1] - b[0] * a[1];
  }
  return s / 2;                    // > 0 — обхід за годинниковою на екрані (вісь y вниз)
}

// Точка всередині многокутника: промінь праворуч, рахуємо перетини (правило парності)
function inside(p, poly) {
  let c = false;
  for (let i = 0, j = poly.length - 1; i < poly.length; j = i++) {
    const a = poly[i], b = poly[j];
    if ((a[1] > p[1]) !== (b[1] > p[1]) &&
        p[0] < (b[0] - a[0]) * (p[1] - a[1]) / (b[1] - a[1]) + a[0]) c = !c;
  }
  return c;
}

// Коло через три точки; null — точки на одній прямій (край буде прямим)
function circle3(a, b, c) {
  const d = 2 * (a[0] * (b[1] - c[1]) + b[0] * (c[1] - a[1]) + c[0] * (a[1] - b[1]));
  if (Math.abs(d) < 1e-9) return null;
  const A = dot(a, a), B = dot(b, b), C = dot(c, c);
  const cx = (A * (b[1] - c[1]) + B * (c[1] - a[1]) + C * (a[1] - b[1])) / d;
  const cy = (A * (c[0] - b[0]) + B * (a[0] - c[0]) + C * (b[0] - a[0])) / d;
  return { c: [cx, cy], r: Math.hypot(a[0] - cx, a[1] - cy) };
}

// Точки дуги від from до to, що проходить через via
function arcPoints(C, from, to, via, n = 120) {
  const ang = p => Math.atan2(p[1] - C.c[1], p[0] - C.c[0]);
  const norm = x => ((x % (2 * Math.PI)) + 2 * Math.PI) % (2 * Math.PI);
  const t0 = ang(from), dTo = norm(ang(to) - t0), dVia = norm(ang(via) - t0);
  const dt = dVia < dTo ? dTo : -(2 * Math.PI - dTo);   // обираємо дугу, на якій лежить via
  const out = [];
  for (let i = 0; i <= n; i++) {
    const t = t0 + dt * i / n;
    out.push([C.c[0] + C.r * Math.cos(t), C.c[1] + C.r * Math.sin(t)]);
  }
  return out;
}
```

## 16. Модель даних кошторису

У `estimate.inputs` додається масив `steps`:

```json
"steps": [
  {
    "id": 1,
    "type": "shelf",
    "edge": "round",
    "scheme": 8,
    "points": [4, 8, 1, 5, 2],
    "wc": 0.5,
    "we": 0,
    "depth_cm": 20,
    "result": { "area_m2": 1.366, "visible_m2": 1.366, "kind": "опукла", "R_m": 1.625, "chord_m": 3.0 }
  }
]
```

- `result` — знімок розрахунку на момент збереження (як знімок цін, D6).
- Значення `depth_cm` — фактичне, а не з налаштувань.

**Для 3D:** використовуємо ті самі многокутники шарів. Кожен шар — горизонтальна площина на глибині h_k, підйоми між рівнями — вертикальні стінки по краю шару.
